# ออกแบบ: สมุดบัญชีแหล่งเงิน (กระทบยอดรายวัน / รายเดือน / รายปี)

คำขอ: ในโมดูลการจัดการเงิน/บัญชี ให้เปิดดูแต่ละแหล่งเงินได้ว่า **เงินเพิ่ม** และ
**เงินลด** เพราะอะไร มีที่มาอ้างอิงกลับไปถึงเอกสารต้นทาง ดูได้ทั้งรายวัน รายเดือน
รายปี และใช้กระทบยอดกับเงินจริงหรือ statement ธนาคารได้

หน้าตาที่เสนอคือแบบ **statement ธนาคาร** — ยอดยกมา, รายการเรียงตามวัน พร้อม
คงเหลือสะสมทุกบรรทัด, ยอดยกไป — ซึ่งเป็นรูปแบบที่คนทำบัญชีเอาไปเทียบกับ
statement จริงได้ทีละบรรทัด

---

## สิ่งที่ต้องรู้ก่อน: มีสามจุดที่ทำให้ยอดเงินผิดอยู่แล้ววันนี้

ตรวจโค้ดตอนออกแบบแล้วเจอสามเรื่อง ต้องแก้ก่อนทำสมุด ไม่อย่างนั้นสมุดจะแสดง
ตัวเลขที่ผิดพร้อมรายละเอียดครบถ้วน ซึ่งทำให้คนเชื่อตัวเลขผิดมากกว่าเดิม

### 1. ปุ่ม "เติมเงินสดย่อย" ในหน้าค่าใช้จ่าย ไม่ถึงยอดเงิน

`topupCash` ใน `app/(app)/accounting/actions.ts` บันทึกลงตาราง `petty_cash`
อย่างเดียว แต่ตั้งแต่ migration 0043 ยอดคงเหลือของทุกแหล่งเงินอ่านการเติมเงินจาก
`money_transfers` — 0043 คัดลอกรายการเติมเงินเก่ามา **ครั้งเดียว** ตอนขึ้นระบบ

แปลว่า **ทุกครั้งที่กดเติมเงินสดย่อยจากหน้าค่าใช้จ่ายหลังขึ้นระบบ ยอดเงินสดย่อย
ไม่เพิ่ม** และแหล่งเงินที่เป็นต้นทางก็ไม่ลด

**ทำแล้ว (migration 0056):** ปุ่มนี้บันทึกเป็นการโอนเข้าบัญชีเงินสดย่อยของสาขาด้วย
ในรายการเดียวกัน และถามว่าเงินมาจากแหล่งไหน (หรือนอกระบบ)

รายการที่ตกหล่นก่อนหน้านี้ **ไม่ถูกคัดลอกให้อัตโนมัติ** — ผูกให้เฉพาะที่ตรงกับการโอนที่มี
อยู่แน่นอน (สาขา วัน จำนวน ตรงกัน) ที่เหลือขึ้นเป็นแผงในหน้าการจัดการเงิน/บัญชี ให้กด
"นำเข้า" พร้อมเลือกว่าเงินมาจากไหน หรือ "โอนไว้เองแล้ว" ทีละรายการ เพราะบางก้อนอาจ
คีย์เป็นการโอนไว้เองแล้วคนละวัน คัดลอกทั้งหมดจะนับเงินซ้ำ

**เจอระหว่างทำ:** `release-0043.sql` (ซึ่งอยู่ใน `release-GO-LIVE.sql`) คัดลอกการเติม
เงินสดย่อยทุกรายการที่ยังไม่มีคู่ไปเป็นการโอน **ทุกครั้งที่รัน** ไม่ใช่ครั้งเดียว การรัน
GO-LIVE บนระบบจริงจึงจะคัดลอกทุกก้อนที่กดหลังขึ้นระบบให้เองก่อน 0056 จะได้ทำงาน
แก้ให้เป็นครั้งเดียวแล้ว พร้อมกับอีกสี่จุดใน GO-LIVE ที่รันซ้ำแล้วทับสิ่งที่ร้านแก้ไปแล้ว
— แหล่งเงินตั้งต้นที่ร้านเปลี่ยนชื่อไปแล้วถูกเพิ่มกลับ (0043/0045), สาขาเชียงใหม่ถูก
เปิด VAT กลับ (0035), รายการประกันในใบงานถูกลบ (0023), และโหน่ง/เคนถูกเพิ่มซ้ำ
(0047) ทดสอบโดยจำลองข้อมูลที่ร้านแก้ไปแล้วทั้งห้าแบบ แล้วรัน GO-LIVE สองรอบ

### 2. อ่านข้อมูลไม่ครบเมื่อเกิน 1,000 แถว

หน้าการเงินและแดชบอร์ดอ่าน ใบงาน/ค่าใช้จ่าย/รับชำระ แบบไม่จำกัดจำนวน แต่
Supabase ตัดผลลัพธ์ที่ 1,000 แถวเงียบๆ (เรื่องเดียวกับที่ทำให้สินค้าในช่องเลือก PO
ผิดสาขา) ค่าใช้จ่ายเชียงใหม่เดือนเดียวก็หลายสิบรายการ รวมทุกสาขาทั้งปีจะเกินแน่

สมุดรายปีจะโดนก่อนใคร **ทำแล้ว:** หน้าการเงินอ่านผ่าน `app/(app)/money/data.ts`
ที่เดียว เป็นหน้าๆ ด้วย `fetchAllRows` แดชบอร์ดก็เปลี่ยนเหมือนกันสำหรับใบงาน PO
ค่าใช้จ่าย และการโอน

### 3. เงินจาก PO ที่ลบแล้ว ยังถูกนับ

ใบงานกรองรายการที่ลบแล้วออก (`deleted_at is null`) แต่ **หน้าการจัดการเงิน/บัญชี
ไม่ได้กรอง PO ขายส่ง** เงินที่รับจาก PO ที่ถูกลบจึงยังอยู่ในยอดคงเหลือของหน้านั้น
(ฉบับแรกของเอกสารนี้เขียนว่าแดชบอร์ดก็ไม่กรอง ซึ่งไม่ถูก — แดชบอร์ดกรองอยู่แล้ว)

**ทำแล้ว:** กรองออกเหมือนใบงาน ถ้า PO ถูกลบทั้งที่รับเงินมาแล้วจริง เงินก้อนนั้นควร
ถูกบันทึกใหม่เป็นรายการโอนเข้าที่มีหมายเหตุ ไม่ใช่ลอยอยู่กับเอกสารที่ไม่มีแล้ว

## 1. สมุดบัญชีแหล่งเงิน

### เข้าจากตรงไหน

ในตารางแหล่งเงินของหน้าการจัดการเงิน/บัญชี กดชื่อแหล่งเงิน → เปิดหน้า
`/money/[บัญชี]` เป็นหน้าของตัวเอง เพื่อให้ส่งลิงก์ บุ๊กมาร์ก และพิมพ์ได้
สิทธิ์ใช้สิทธิ์เดียวกับหน้าการเงิน (`money`)

### ด้านบน

- เลือกแหล่งเงิน (สลับบัญชีได้โดยไม่ต้องย้อนกลับ)
- ช่วงเวลา: **รายวัน / รายเดือน / รายปี / ช่วงเวลา** — ใช้ตัวเลือกช่วงเวลาชุดเดียวกับ
  หน้าอื่นในระบบ
- การ์ดสี่ใบ: **ยอดยกมา · เงินเพิ่ม · เงินลด · ยอดยกไป**
- แถบกระทบยอดล่าสุดของบัญชีนี้ในช่วงนั้น: ยอดที่นับได้ ยอดระบบ ผลต่าง

### ตาราง

| คอลัมน์               | เนื้อหา                                               |
| --------------------- | ----------------------------------------------------- |
| วันที่                | วันที่เงินเคลื่อนจริง (ดูตารางที่มาข้างล่าง)          |
| รายการ · ที่มาอ้างอิง | ประเภท + เลขเอกสาร (กดไปเอกสารต้นทางได้) + รายละเอียด |
| เงินเพิ่ม / เงินลด    | ช่องใดช่องหนึ่ง                                       |
| คงเหลือ               | คงเหลือสะสมหลังรายการนั้น                             |

- **รายวัน / รายเดือน** แสดงทุกรายการ
- **รายปี** รวมเป็นแถวละเดือน (ยกมา · เพิ่ม · ลด · สิ้นเดือน) กดเดือนเพื่อลงไปดูรายการ
- ยอดยกไปของสมุด **ต้องเท่ากับ** ยอดคงเหลือในตารางแหล่งเงินและบนแดชบอร์ดเสมอ
  เพราะคำนวณด้วยฟังก์ชันเดียวกัน ถ้าไม่เท่าคือบั๊ก และจะมีเทสต์ล็อกไว้

### ที่มาของแต่ละรายการ

| ประเภท           | มาจาก                                | วันที่ที่ใช้                    | อ้างอิงที่แสดง                                   | กดไปที่              |
| ---------------- | ------------------------------------ | ------------------------------- | ------------------------------------------------ | -------------------- |
| รับชำระใบงาน     | `ticket_payments`                    | `paid_at`                       | เลขใบงาน · ชื่อลูกค้า · ทะเบียน · มัดจำ/ชำระเต็ม | ใบงาน · สลิปที่แนบ   |
| รับชำระขายส่ง    | `order_payments` ที่ **รับเงินแล้ว** | วันยืนยันรับเงิน (`cleared_at`) | เลข PO · ร้านลูกค้า · เลขเช็ค/ธนาคาร             | PO                   |
| ค่าใช้จ่าย       | `expenses` ที่ **จ่ายแล้ว**          | `paid_at`                       | เลขเอกสาร POS-… · รายการ · กลุ่มค่าใช้จ่าย       | ไฟล์แนบของค่าใช้จ่าย |
| โอนเข้า / โอนออก | `money_transfers`                    | `moved_at`                      | แหล่งเงินฝั่งตรงข้าม (หรือนอกระบบ) · หมายเหตุ    | สมุดของบัญชีฝั่งนั้น |
| ยอดตั้งต้น       | `money_accounts.opening_balance`     | `opened_at`                     | "ยอดตั้งต้น"                                     | —                    |
| กระทบยอด         | `money_reconciliations`              | `counted_at`                    | ยอดที่นับได้ · ผลต่าง · หมายเหตุ                 | —                    |

- เช็คที่ยัง **แจ้งแล้ว** แต่ยังไม่ยืนยัน และค่าใช้จ่าย **รอจ่าย** ไม่ขึ้นในสมุด —
  สมุดคือเงินที่เคลื่อนแล้วจริง (ร้านยืนยัน: ยังไม่ได้รับเงิน ไม่นับ)
- บรรทัดกระทบยอด **ไม่เปลี่ยนยอด** เป็นหมุดหลักฐานว่า ณ วันนั้นนับได้เท่าไหร่
- คนที่ไม่มีสิทธิ์เปิดใบงานหรือขายส่ง เห็นเลขอ้างอิงเป็นตัวหนังสือ ไม่มีลิงก์

## 2. กระทบยอดย้อนวันที่ได้

วันนี้การกระทบยอดบันทึกได้แค่ "วันนี้" และเก็บยอดระบบ ณ ตอนกด แต่ statement
ธนาคารออกสิ้นเดือน และมักได้มาต้นเดือนถัดไป

ข้อเสนอ:

- เลือก **วันที่ของยอดที่นับ** ได้ เช่น 30 ก.ย.
- ยอดระบบคำนวณที่ **เซิร์ฟเวอร์** ณ สิ้นวันนั้น ไม่รับตัวเลขจากหน้าจอ
- กดบันทึกกระทบยอดจากหน้าสมุดได้เลย โดยเติมวันที่สุดท้ายของช่วงที่กำลังดูให้
- ถ้ามีรายการย้อนหลังถูกแก้ภายหลังจนยอดระบบของวันนั้นเปลี่ยน สมุดจะเตือนว่า
  "ยอดระบบ ณ วันกระทบยอดเปลี่ยนไปจากตอนบันทึก" แทนที่จะแก้ประวัติเงียบๆ

## 3. ส่งออก

ปุ่ม Excel และ PDF แบบเดียวกับหน้าค่าใช้จ่าย ใช้ข้อมูลชุดเดียวกับที่เห็นบนจอ

## ลำดับการทำ

1. **แก้สามจุดที่ทำให้ยอดผิด** (ปุ่มเติมเงินสดย่อย, อ่านข้อมูลไม่ครบ, PO ที่ลบแล้ว)
   ต้องมี migration สำหรับคัดลอกรายการเติมเงินสดย่อยที่ตกหล่น
2. **สมุดบัญชีแหล่งเงิน** รายวัน/รายเดือน/รายปี พร้อมที่มาอ้างอิงและลิงก์
3. **กระทบยอดย้อนวันที่** และหมุดกระทบยอดในสมุด
4. **Excel / PDF**

ข้อ 2–4 ไม่ต้องเพิ่มตาราง ใช้ข้อมูลที่มีอยู่แล้วทั้งหมด ข้อ 3 เปลี่ยนแค่วิธีบันทึก

## ที่ร้านตัดสินใจแล้ว (14 ก.ย. 2569)

1. **ปุ่มเติมเงินสดย่อยในหน้าค่าใช้จ่าย** — บันทึกเป็นการโอนด้วย และถามว่าเงินมาจากไหน
2. **รายการเติมเงินสดย่อยที่ตกหล่น** — ร้านไม่ได้ตอบข้อนี้ จึงเลือกทางที่ไม่นับเงินซ้ำ:
   ไม่คัดลอกให้อัตโนมัติ ขึ้นเป็นแผงให้นำเข้าหรือข้ามทีละรายการ (ดูข้อ 1 ด้านบน)
3. **เงินจาก PO ที่ลบแล้ว** — ไม่นับ เหมือนใบงาน
4. **รายเดือน** — แสดงทุกรายการ
5. **เงินที่ยังไม่ได้รับจริง** (เช็คที่ยังไม่ยืนยัน ค่าใช้จ่ายรอจ่าย) — ไม่นับ และไม่แสดงในสมุด
